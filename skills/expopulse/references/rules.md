# ExpoPulse rules (0.2.0)

All 59 rules, with the default severity, whether `expopulse fix` can fix it, and what to check before trusting or acting on a finding. Severities can be changed per project in the ExpoPulse config, so the JSON's `severity` field is what counts for a given run.

**Bucket** refers to `triage.md`: B = release blocker, R = store-review risk, S = size, P = runtime performance, H = hygiene.

## Android

If `android/` is generated by prebuild (gitignored or absent), fix these in `app.json` (`android.permissions`, `blockedPermissions`, `expo-build-properties`), not in the native files.

| Rule | Default | Auto-fix | Bucket | Check before acting |
|---|---|---|---|---|
| `android/target-sdk-outdated` | error | — | B | Play rejects updates below the minimum target. Usually fixed by the SDK upgrade or `expo-build-properties`; retest permissions and background work. |
| `android/dangerous-permission` | warning | — | R | Find which feature (or library) needs it. Remove unneeded ones with `blockedPermissions` / `tools:node="remove"`; required ones need a Play Console declaration. |
| `android/duplicate-permission` | warning | yes | H | Safe to auto-fix in a committed `android/`. In a CNG project, find which plugin adds the copy instead. |
| `android/deprecated-permission` | info | — | H | Informational. |
| `android/cleartext-traffic-enabled` | warning | — | R | Check whether it is only for a dev server; restrict with a network security config instead of enabling globally. |
| `android/minify-disabled` | warning | — | S | Enabling R8 needs a release-build test pass; reflection-only classes may need `-keep` rules. |
| `android/shrink-resources-disabled` | info | — | S | Pair with minify; test the release build. |
| `android/allow-backup-enabled` | info | — | H | Privacy consideration for apps storing tokens or personal data. |
| `android/no-abi-splits` | info | — | H | Irrelevant when shipping AAB to Play (Play splits per device). Matters for APK distribution. |
| `android/min-sdk-low` | info | — | H | Informational. |

## iOS

Same CNG rule: fix in `app.json` → `ios.infoPlist` / `ios.privacyManifests` when `ios/` is generated.

| Rule | Default | Auto-fix | Bucket | Check before acting |
|---|---|---|---|---|
| `ios/missing-usage-description` | error | — | B | Hard App Review rejection and a runtime crash on the permission prompt. Confirm the feature really requests the permission. |
| `ios/empty-usage-description` | error | — | B | Usually a config plugin with no string supplied. Set the plugin option. |
| `ios/generic-usage-description` | warning | — | R | Rewrite to name the feature and benefit ("Photos you attach to a report are uploaded with it"). Draft wording for the user; don't invent features. |
| `ios/arbitrary-loads-enabled` | warning | — | R | Prefer per-domain exceptions; App Review asks for justification. |
| `ios/missing-privacy-manifest` | warning | — | B | Treat as a blocker: App Store Connect flags missing required-reason API declarations. Recent SDKs generate it during prebuild. |
| `ios/missing-encryption-declaration` | info | — | H | Saves a manual export-compliance question on every upload. |
| `ios/background-mode-unjustified` | info | — | R | Check the feature exists; unused background modes draw review questions. |
| `ios/deployment-target-low` | info | — | H | Informational. |

## Assets

Reference detection is **textual**: a file name that never appears in source or `app.json` is "unused". Before deleting anything, search for the name without extension, template-string `require`s, asset index files, remote config, and native code.

| Rule | Default | Auto-fix | Bucket | Check before acting |
|---|---|---|---|---|
| `assets/unused-asset` | warning | yes | S | Verify as above. Native `res/` and `*.xcassets` are already excluded. |
| `assets/unused-font` | warning | yes | S | Fonts are often loaded by family name in `useFonts({...})` or a config plugin; search the family name too. |
| `assets/duplicate-image` | warning | yes | S | **Do not auto-fix if more than one copy is referenced**: 0.2.0 deletes the redundant copy without updating its `require`. Re-point the references by hand, then delete. |
| `assets/oversized-image` | warning | yes | S | The fix re-encodes in place (lossy). Ask whether design-critical images (brand, splash) may be recompressed; check visually afterwards. |
| `assets/oversized-asset` | warning | — | S | Videos, Lottie, JSON: consider streaming from a CDN instead of bundling. |
| `assets/image-dimensions-excessive` | info | — | S | Resize to 3× the largest rendered size. |
| `assets/prefer-webp` | info | yes | S | Only applied with `fix --webp`; it changes file extensions and leaves every import for you to update. Usually do it by hand. |
